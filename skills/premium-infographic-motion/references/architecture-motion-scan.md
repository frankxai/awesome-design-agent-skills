# Architecture motion scan

Use this pattern when a sourced architecture plate, layered stack, system map, or technical cutaway is too dense to read as one social frame.

## Purpose

Motion should reveal the architecture's reading path without falsifying its topology. The viewer receives one responsibility at a time, then sees the whole system resolve.

## Required semantic work

Before motion, store:

- the bounded system and its explicit responsibilities;
- every node, edge, direction, condition, and source;
- whether the visual is a layer, peer taxonomy, runtime sequence, decision tree, or state machine;
- cross-cutting controls such as evaluation, observability, governance, access, privacy, cost, security, and human approval;
- the exact difference between editorial reveal order and runtime order.

A numbered reveal is a claim. If numbers indicate reading order rather than chronology or priority, say so in the semantic model and long description.

## Motion structure

1. **Hook:** interrupt one weak mental model in the first 1–2 seconds.
2. **Whole-system reveal:** show the full architecture before or immediately after the hook so the audience understands that the parts belong together.
3. **Semantic scan:** isolate one responsibility at a time with a stable camera or deliberate move, one exact label, and one connector or focus device.
4. **Cross-cutting rail:** resolve evaluation, governance, security, or human control across all affected responsibilities.
5. **Whole-system hold:** return to the complete architecture with one takeaway and one CTA.

Do not convert a bounded system into a fake left-to-right pipeline merely because a timeline is linear.

## Reuse-before-regenerate

Search the approved asset mirror before creating another source image. Reuse an existing source when all are true:

- it is inspected and has an output path plus provenance;
- it carries the required physical subject or metaphor;
- it contains no public text, generated marks, or incorrect authoritative topology;
- the target crops and motion focus zones remain usable;
- reusing it does not misrepresent a different brand, version, or claim set.

Record the source hash and original prompt packet. A zero-call reuse is a quality and cost decision, not a shortcut. Regenerate when the concept, subject, hierarchy, rights, or crop is wrong.

## Social formats

- Author 1080 × 1920 and 1080 × 1350 as separate compositions. Do not crop one blindly into the other.
- Keep the hook readable without audio by 1.6 seconds.
- Use safe margins for player UI and platform crops.
- Use 20 px minimum body type, 60 px minimum hero type at 1080-wide video unless the delivery test proves a smaller size remains readable.
- Hold each technical statement long enough to read silently.
- Design a reduced-motion poster that contains every essential claim.

## Runtime router

- **HyperFrames + GSAP:** preferred for one-off editorial scan choreography, deterministic SVG rules, masks, and frame inspection.
- **Remotion:** preferred for a reusable series with typed data, repeatable layer components, and programmatic derivatives.
- **Motion for React:** use for an interactive web companion, not as the default rendered video lane.
- **Generated video:** optional physical source footage only; never authoritative public copy or architecture topology.

Compare actual exports from the same semantic master. Measure time to first usable, repair count, phone-scale readability, editability, render time, and exposed cost. Tool reputation is not a verdict.

## Silent-first audio route

Design the visual to work with no sound. If channel guidance favors audio, add native or commissioned audio only after visual approval. Treat audio as reinforcement: one hook impact, restrained layer ticks, and a final resolve are usually enough. Do not use narration to rescue unreadable typography.

## Hard failures

- Cross-cutting governance appears as a final optional stage.
- Animation invents arrows, dependencies, or sequence not in the semantic model.
- The architecture disappears behind equal-weight cards.
- Camera motion continues while dense copy must be read.
- The final frame never returns to the whole system.
- A new image is generated even though an approved, compatible source already exists and the run records no reason.
